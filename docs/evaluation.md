# 验证协议、质量与真实收益

## 1. 当前交付的验收边界

首版以离线 mock 验证网关行为。运行不需要真实云密钥、Ollama、模型下载或 GPU 租赁。测试命令为：

```bash
.venv/bin/python -m pytest
```

本文定义验收方法。mock 产生的文本、usage 和耗时不用于声称真实模型质量、真实性能、费用或节省比例。

| 验证方向 | 必要场景与通过条件 |
| --- | --- |
| 默认行为 | 启动、健康检查、模型列表和统计接口可用；mock 运行不访问外部服务；原云模型 ID 不触发本地模型 |
| 请求与错误透传 | 系统消息、代码、工具定义、调用 ID、工具结果、结构化输出参数与扩展字段保持完整；上游错误状态可观察 |
| SSE | UTF-8 中文跨网络块、事件跨块、多事件同块、结束前 usage、`[DONE]` 均保持完整与原顺序；协议解析不改变输出 |
| 工具与取消 | 多工具索引和分段 JSON 参数保持原样；客户端取消关闭上游；开始输出后的错误不触发再次生成或重复工具事件 |
| 本地路由 | 只有显式 local-json 且满足范围的请求进入本地；普通文本、多消息、工具和不适用格式不能因输入短而被隐式降级 |
| 上下文路径 | 三条路由可重复执行；只有可选块进入筛选；实际云请求等于 Working Context；Raw Context 在内存中完整保留；正文快照仅在显式 opt-in 评测中保存 |
| 上下文保护 | 系统、当前任务、约束、代码、数字、否定、路径、JSON、完整 traceback 不被改写；工具链整体保护；模型只选择 ID |
| 上下文失败 | 非法选择、未知 ID、超时恢复全量；未完整展示给 worker 的块保留；没有净缩减则发送全量 |
| 输出与回退 | 完整 Schema 检查类型、required、additionalProperties 及嵌套约束；本地超时、非法 JSON 或校验失败只能在交付前最多转云一次 |
| 缓存 | 全局默认关闭；allow、bypass、refresh、无请求头分别正确；过期、内容或模型模板配置变化导致未命中；仅本地成功结果可缓存；命中不调用模型 |
| 用量与费用 | 完整任务关联各次尝试；真实/mock 来源可区分；缺 usage 或价格时不补零；缓存计费和输出内推理 token 不重复计数 |

Schema 检查成功仅说明结果符合结构。示例输入中的 `amount=120` 输出为 `amount=121` 仍可能满足 Schema，因此真实数据准确率需要独立评估。

## 2. 100 个脱敏任务的对照设计

建议首次建立如下样本，总计 100 个；40 个用于调整模板与策略，60 个留出评测。将同一原始资料、代码库问题或近重复任务放入同一集合，避免调整过程中接触留出答案。

| 任务类别 | 调整集 | 留出集 | 主要检查 |
| --- | ---: | ---: | --- |
| 独立文本与字段提取 | 12 | 18 | 字段、数值、单位、否定、缺失值、格式转换正确性 |
| 长资料问答 | 8 | 12 | 全量与筛选资料对照；核对来源、证据召回、关键约束与答案完整性 |
| 普通开发问答 | 8 | 12 | 可选文档筛选后仍由云推理；核对技术正确性、可执行性与遗漏 |
| 多步编程任务 | 12 | 18 | 测试、修改正确性、回归、工具行为与人工返工；首版走云端 |
| 合计 | 40 | 60 | 同时覆盖可分流和应透传的请求 |

每个任务保留脱敏输入、预期或判分规则、任务类别、基线模型配置、起始状态、结果与人工复核记录。模型自己评分只能作辅助，不能独自决定通过。

基线和优化组使用相同云模型、生成参数和任务起点，先测试透传，再优先比较全量与筛选上下文，本地提取和精确缓存各自独立评估。测试顺序应交错安排并记录运行时间，减少上游负载变化影响。编程任务从相同仓库状态开始，统计到任务完成或明确失败，不只比较第一轮回答。

上下文 A/B 使用完全相同的 messages、资料块、constraints 和云模型。A 设置 `gateway_context.optimize=false`，B 设置 true，其他配置保持一致；示例在 `examples/context_baseline.json` 和 `examples/context_request.json`。先用相同包装格式排除包装差异，再增加供应商直连全量请求验证网关透传开销。不要用“基线散文、优化组结构化”的不同原始资料混作对照。

在调用云端之前，为留出任务人工标注必须保留的证据块，检查选择后的证据召回率、关键约束完整率及来源切片一致性。即使字节数显著减少，遗漏关键证据的任务也判为失败。mock 的关键词选择只验证数据路径，不用于这项质量评测。

云供应商的原生提示缓存状态需要记录或在两组中按同样方法控制，避免把一组的热缓存优势误归因于网关。本地模型冷启动与热运行分别统计。

精确缓存的日常收益应来自自然工作中的重复请求。人为把同一请求重复几十次，只能用来测试缓存机制，不能进入日常收益结论。

## 3. 用量、费用和延迟口径

客户端用相同的 `X-Gateway-Task-ID` 关联同一完整任务的多轮请求。计算时包含本地尝试、云端回退、额外请求及人工修正引发的调用；首版云端无自动重试，但客户端发出的重试仍要计入。

```text
完整任务云端 token = 各次云端尝试的输入 token + 输出 token

云端 token 降幅
  = 1 - 优化组完整任务云端 token / 基线完整任务云端 token

总净节省
  = 基线 API 费用
    - 优化组 API 费用
    - GPU 租赁、存储与网络费用
    - 其他新增运行费用
```

当基线 token 为零，降幅没有定义，不输出百分比。缺失用量的任务不生成确定节省率，另报完整任务数、缺失数及缺失原因，避免只挑选记录完整的成功样例。

- 输入、输出分别报告。供应商若将推理 token 包含在输出中，不再相加；缓存读 token 若已经包含在输入中，不再相加为逻辑总 token。
- `raw_input_tokens` / `working_input_tokens`（亦提供 raw_context_tokens / working_context_tokens）始终是统一 UTF-8 字节数除以四的估算，`context_compression_ratio = working/raw`。它们用于比较发送内容，不能代替供应商 usage；默认只保留字节数和结构化指标，实际提交对象仅在显式评测/调试 artifact 中保存。
- `usage_source` 取 actual / estimated / unknown，模拟数据另标记 simulated。`compare_runs` 只接受真实、完整云用量和非零基线；质量未经确认时，不给出“质量不下降的节省已验证”结论。
- API 费用按供应商计费类别与配置价格计算。读取缓存和写入缓存的计费规则可能不同，不能统一假设免费。
- SSE 最后一个 usage 事件可能因断流而缺失。响应中断并不说明供应商没有消耗 token，计量应标记未知或不完整。
- 未配置价格或计费类别不支持时，费用保持未知，不能记作零。真实 API 账单是费用核对依据，网关结果是基于已知 usage 与价格的计算值。
- 报告完整任务首字延迟、总耗时及 P50/P95；样本量不足时注明百分位不稳定。客户端编排时间和人工返工需要另行记录，单次 HTTP 请求统计不等于完整任务体验。

## 4. 验收目标与预算

| 方向 | 首轮目标 |
| --- | --- |
| 质量 | 留出集任务通过率不低于基线，数字、否定、代码等关键约束全部通过 |
| 编程正确性 | 同一起点下检查测试、修改范围与回归，记录人工返工 |
| token | 完整任务云端总 token 降低 20%，同时保留各任务类别分项结果 |
| 总成本 | 加入新增运行成本后低于基线；一次性评测费用独立报告 |
| 延迟 | 同类任务 P95 总耗时增幅不超过 20%，冷启动单列 |
| 协议 | 无内容或工具参数改写、无静默重试与重复工具事件 |

以上是目标，不是本次实现已达到的结论。60 个留出任务仅提供初步证据，不能据此宣称通用“无损压缩”或普遍稳定节省。若日常工作多数为复杂编程，允许本地分流比例可能很低；此时应如实报告，不扩大白名单以追求目标数字。

任何真实评测都必须先确认云供应商、模型、价格、任务数与本轮付费上限，再配置环境变量。本次发布验证不调用真实云模型、下载模型或租用 GPU。

GPU 启用前需同时验证质量、延迟、GPU、存储、网络、闲置和失败回退总成本，不能把远程 GPU 当作无成本的既有资源。

## 5. 发布可复现结论

开源发布时附代码版本、配置、模型与 revision、硬件、日期、样本划分、判分规则、失败案例、实际测试结果和脱敏复现步骤。固定 mock 测试与真实模型实验分别展示。

公开材料不含真实工作对话、个人信息、密钥、`.env`、缓存数据库或受限模型权重。某项策略未通过质量或成本验收时保持关闭，并记录适用范围与失败结果。

## 6. 已实现：36 个危险案例自动 A/B

独立入口 `.venv/bin/python -m edge_cloud_gateway.danger_eval --dry-run` 可自动执行 12 类各 3 个案例、确定性答案判定、must_keep 来源检查，以及 JSON / CSV / 中文报告。默认完全离线；真实调用需 `--live` 并在终端确认费用。具体数据、强制路由、指标、失败归因和使用方法见 [危险案例 A/B 评测说明](danger-ab-evaluation.md)。本套件是上述更大留出集评测的补充，模拟结果不是模型能力或真实节省结论。
